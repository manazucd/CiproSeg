CiproSeg

A PyTorch framework for binary cell segmentation with Leave-One-Series-Out cross-validation

v0.1.0
Python 3.9+ PyTorch 2.2+ Apache-2.0 Single GPU

CiproSeg trains a U-Net on time-series microscopy data, holding out one experimental series at a time for testing. Each fold gets its own checkpoint, validation curves, and test metrics. At the end you have a per-fold breakdown of segmentation performance across the entire dataset with no data leakage, deterministic seeds, and a single config file controlling the whole run.

The framework was built for E. coli fluorescence microscopy experiments involving ciprofloxacin-treated and control populations, though it works with any binary segmentation task that follows the expected directory structure.

LOSO Cross-Validation

Each experimental series is held out once as the test set. No data leakage, no cherry-picked folds.

Self-Contained Checkpoints

Every saved .pt file stores the full config, model weights, optimizer state, and fold metadata. Evaluate months later without hunting for config files.

Tiled Inference

Images larger than the training patch are split into overlapping tiles with averaged predictions in overlap regions. Padding handles small images automatically.

One Config, Full Run

A single YAML file controls model architecture, training hyperparameters, data paths, and scheduling. No scattered settings across multiple files.

Installation

Clone the repository and install in editable mode:

git clone https://github.com/manazucd/CiproSeg.git
cd CiproSeg
pip install -e .

For development (adds pytest, ruff, mypy):

pip install -e ".[dev]"

If your TIFF files use LZW or similar compression, you will also need:

pip install imagecodecs

Verify that the CLI entry points are working:

ciproseg-train --help
ciproseg-eval  --help
ciproseg-infer --help
Requirements
Python 3.9 or newer and PyTorch 2.2 or newer. A CUDA GPU is recommended for training but not required. The full dependency list is in requirements.txt.

Quick Start

Once installed, a complete training run takes three steps:

1

Organise your data

Place images and masks into matched directory trees with one subfolder per experimental series. See Dataset Layout for the full specification.

2

Edit the config

Open configs/experiment.yaml and set dataset.root to the path of your data folder. Adjust model.name, patch size, epochs, and other parameters as needed.

3

Run training

Launch the LOSO training loop. The framework handles fold construction, checkpointing, validation, and test evaluation automatically.

ciproseg-train --config configs/experiment.yaml

When training completes, results are written to a timestamped directory under runs/. Each fold gets its own checkpoint, training curves, and test metrics.

You can also run training from Python directly:

from ciproseg.utils.config import load_config
from ciproseg.core.engine import Engine

cfg = load_config("configs/experiment.yaml")
Engine(cfg).fit()

Dataset Layout

CiproSeg expects images and masks in matched directory trees. Each subdirectory under images/ and masks/ represents one experimental series. One series is held out per LOSO fold.

your_data/ images/ series_A/ frame_000.tif frame_001.tif ... series_B/ ... masks/ series_A/ frame_000.tif frame_001.tif ... series_B/ ...

Filenames must match exactly between images/<series>/ and masks/<series>/. The build step will raise an error if there is any mismatch. Supported formats are .tif, .tiff, .png, .jpg, and .jpeg.

Masks should be binary: any nonzero pixel is treated as foreground. Internally, the framework reads masks with a threshold of 128, so values of 255 for foreground and 0 for background work well.

You can verify that your dataset is correctly paired by running the included check tool:

python tools/check_dataset_pairs.py /path/to/your_data

Training

ciproseg-train --config configs/experiment.yaml

This builds a LOSO cross-validation loop: for N series, N folds run sequentially. Each fold trains on N-1 series (split 80/20 into train/val by temporal order), then evaluates on the held-out series. Best checkpoints are selected by validation Dice score.

You can override the seed or force CPU mode from the command line:

ciproseg-train --config configs/experiment.yaml --seed 42
ciproseg-train --config configs/experiment.yaml --cpu

Output structure

Each run creates a unique timestamped directory. Nothing is ever overwritten.

runs/unet4/2026-04-03_153000/ config.yaml config_resolved.yaml train.log run_summary.pt run_summary.json fold_01_test_seriesA/ best.pt best.json last.pt last.json loss.png dice.png fold_02_test_seriesB/ ...

config.yaml is the experiment config as passed in. config_resolved.yaml includes all runtime overrides and the resolved output path. train.log captures epoch losses, validation metrics, and fold summaries. Each fold directory contains the best and latest checkpoints, JSON sidecars with metadata, and training curve plots.

Checkpoint contents

Every .pt file is a dictionary with the following keys:

KeyDescription
modelModel state dict (weights and buffers)
optimOptimizer state dict
schedScheduler state dict (or None)
cfgFull experiment config used for the run
fold_nameFold identifier, e.g. fold_01_test_seriesA
fold_idNumeric fold index
best_val_metricBest validation Dice observed during training
epochEpoch at which checkpoint was saved

The JSON sidecar files (best.json, last.json) store the same metadata minus the large tensors, so you can browse results without calling torch.load.

Evaluation

Point ciproseg-eval at any checkpoint. Everything it needs is stored inside the .pt file:

ciproseg-eval --ckpt runs/unet4/.../fold_01_test_seriesA/best.pt

The evaluator loads the model architecture from the saved config, restores the weights, identifies the held-out test series from the fold name, and runs tiled inference over every frame in that series.

Output is printed to the terminal:

------------------------------------------------------------
  Checkpoint : runs/.../fold_01_test_seriesA/best.pt
  Fold       : fold_01_test_seriesA
  Test series: seriesA
------------------------------------------------------------
  Dice       : 0.8234
  IoU        : 0.7012
  Precision  : 0.8456
  Recall     : 0.8019
  Loss (BCE) : 0.14523
------------------------------------------------------------

Useful flags

FlagPurpose
--json metrics.jsonWrite metrics to a JSON file
--cpuForce CPU evaluation
--dataset-root /new/pathOverride the dataset path stored in the checkpoint
--patch 512 --stride 256Override tiling parameters
--thr 0.45Use a different binarisation threshold

Inference

Run a trained model on a directory of images to produce segmentation masks and overlays:

ciproseg-infer \
  --ckpt runs/.../fold_01_test_seriesA/best.pt \
  --input path/to/images/seriesA/

For each input image (say frame_001.tif), the following files are written:

FileDescription
frame_001_prob.png16-bit probability map (0 = background, 65535 = cell)
frame_001_binary.pngBinary mask after thresholding (0 or 255)
frame_001_pred_overlay.pngInput image with predicted boundaries drawn in green

When you also provide ground-truth masks with --masks, two additional files are generated per image:

FileDescription
frame_001_gt_overlay.pngInput image with ground-truth boundaries in cyan
frame_001_diff.pngColour-coded difference map: TP green, FP red, FN blue, TN dark

Full example

ciproseg-infer \
  --ckpt .../best.pt \
  --input path/to/images/seriesA/ \
  --masks path/to/masks/seriesA/ \
  --output predictions/seriesA/ \
  --threshold 0.45 \
  --patch 512 \
  --stride 256

Other options: --cpu, --device cuda:1, --verbose (enables DEBUG-level per-file logging).

Configuration Reference

The experiment config (configs/experiment.yaml) is the single source of truth for a CiproSeg training run. All sections are described below.

dataset

FieldDescription
nameDataset loader identifier. Currently only ciproseg_ecoli is supported.
rootAbsolute path to the dataset directory containing image/mask pairs.
train_fracFraction of non-test frames used for training within each fold. The remainder becomes the validation set. Default: 0.8.
patchCrop size in pixels for training patches. Must be divisible by 16 for unet4 or by 4 for unet2.
strideStride for tiled inference on validation and test frames. Smaller values produce smoother predictions at the cost of speed.

model

FieldDescription
nameArchitecture variant. unet2 uses 2 encoder/decoder levels; unet4 uses 4 levels (recommended).
in_channelsNumber of input channels. Set to 1 for grayscale microscopy.
out_channelsNumber of output channels. Set to 1 for binary segmentation.
base_channelsFeature maps in the first encoder block. Doubles at each subsequent level.

trainer

FieldDescription
epochsTraining epochs per fold.
batch_sizePatches per gradient step.
num_workersDataLoader workers. Set to 0 for debugging.
seedBase random seed. Each fold derives its seed as seed + 1000 * fold_id.
thrSigmoid threshold for binarising model output during evaluation.
target_patches_per_epochControls how many random crops are sampled per epoch. The per-frame crop count is derived from this.
deterministicEnables PyTorch deterministic mode. Slower but fully reproducible.
benchmarkEnables cudnn.benchmark. Faster on fixed input sizes.
cpuForce CPU training even when a GPU is available.
output_dirRoot directory for outputs. Each run creates a timestamped subdirectory.

optim

FieldDescription
nameOptimizer. Supported: adam, adamw (default), sgd.
lrInitial learning rate.
weight_decayL2 regularisation. Bias and normalisation parameters are automatically excluded.

sched

FieldDescription
nameScheduler. none keeps the LR constant. Also supports cosine, step, and onecycle.
tmax(Cosine only) Epochs over which the LR anneals from lr to zero.

logger

FieldDescription
nameLogger identifier used in log output.
levelLogging verbosity: DEBUG, INFO, WARNING, ERROR.

Example config

# configs/experiment.yaml

dataset:
  name: ciproseg_ecoli
  root: "/path/to/your_data"
  train_frac: 0.8
  patch: 256
  stride: 128

model:
  name: unet4
  in_channels: 1
  out_channels: 1
  base_channels: 64

trainer:
  epochs: 500
  batch_size: 2
  num_workers: 4
  seed: 1234
  thr: 0.5
  target_patches_per_epoch: 1000
  deterministic: false
  benchmark: true
  cpu: false
  output_dir: "runs"

optim:
  name: adamw
  lr: 1.0e-4
  weight_decay: 1.0e-4

sched:
  name: cosine
  tmax: 250

logger:
  name: ciproseg
  level: INFO

SLURM / HPC

Job scripts for GPU and CPU-only partitions are provided in scripts/:

sbatch scripts/slurm_gpu.sh    # GPU partition
sbatch scripts/slurm_cpu.sh    # CPU-only partition

Both scripts auto-detect the project root relative to the submission directory. Thread counts for CPU-bound operations (OpenMP, MKL, OpenBLAS) are set from SLURM_CPUS_PER_TASK automatically.

Training output goes to train.log inside the timestamped run directory. SLURM's own slurm-<jobid>.out captures driver errors, OOM kills, and other system-level messages.

Tip
Submit from the project root or the scripts/ directory. The scripts walk up one level if needed to find configs/experiment.yaml.

How It Works

Engine

The Engine orchestrates runs but contains no task logic of its own. It lazily builds the Trainer on first access, so evaluation-only workflows never touch training code. On fit(), it delegates to the Trainer and fires lifecycle hooks at the end.

Trainer

The Trainer owns the full LOSO loop. It builds the dataset index, creates N folds (one per series), and trains each fold sequentially. Within each fold, it constructs a fresh model, optimizer, and scheduler, then runs the training loop with periodic validation. Best checkpoints are selected by validation Dice. After all epochs are done, it loads the best weights and runs final test evaluation on the held-out series.

Each fold gets a deterministic seed derived from the base seed (seed + 1000 * fold_id), so results are reproducible even when folds run in sequence.

Evaluator

The evaluate_checkpoint() function is fully standalone. It loads a checkpoint, rebuilds the model from the config stored inside it, identifies the held-out test series from the fold name, and runs tiled inference. No config file needed.

Checkpointer

Handles atomic file writes using a temporary file followed by os.replace(), both for fold-level checkpoints and the run summary. JSON sidecars carry metadata without requiring torch.load to browse results.

Tiled inference

Handles images larger than the patch size by splitting them into overlapping tiles, running each through the model, and averaging predictions in overlap regions. Tile positions are computed deterministically to ensure full coverage. Padding is applied automatically when an image or tile is smaller than the patch size.

Hook system

A lightweight lifecycle hook system fans out calls at key points: train start/end, fold start/end, epoch start/end, batch start/end, and eval start/end. The built-in ProgressBar hook handles all console and file logging. You can add custom hooks by subclassing Hook and overriding the methods you need.

Models

CiproSeg ships with two U-Net variants, both registered through a decorator-based model registry.

UNet4 (default)

A standard 4-level encoder/decoder U-Net. Four downsampling stages with max pooling, a bottleneck, and four upsampling stages with transposed convolutions and skip connections. Each block is a double convolution (Conv2d, BatchNorm, ReLU, repeated). With base_channels=64, this model has roughly 31 million parameters.

Requires input dimensions divisible by 16.

UNet2 (lightweight)

A reduced 2-level U-Net with the same double-convolution building blocks. Significantly fewer parameters, faster to train. Useful for debugging, quick experiments, or very small datasets.

Requires input dimensions divisible by 4.

Model registry

Models are registered with the @register_model decorator:

from ciproseg.models.registry import register_model

@register_model("my_model")
def build_my_model(**kwargs):
    return MyModel(**kwargs)

The registry is populated at import time. The models/__init__.py file eagerly imports all built-in model modules to ensure their decorators fire before any code tries to look up a model by name.

Data Pipeline

Index building

build_index() scans the dataset root, matches image/mask filenames, and returns a dictionary mapping series names to lists of FrameItem dataclass instances. It validates that every image has a corresponding mask and raises a clear error on mismatch.

Fold construction

make_loso_folds() produces one fold per series. For each fold, build_fold_splits() splits the remaining series by temporal order: the first 80% of frames (by default) become training data, the last 20% become validation data. This temporal split avoids information leakage from future frames into training.

Patch sampling

Training uses RandomCropSegDataset, which draws random crops from full-resolution frames on the fly. The sampling strategy is a weighted mixture of three modes:

ModeDefault weightBehaviour
Foreground60%Centres patches on foreground pixels
Boundary30%Centres patches on morphological boundaries
Random10%Uniform random placement

The number of crops per frame per epoch is derived from target_patches_per_epoch, clamped between configurable bounds.

Augmentation

Image/mask pairs are augmented consistently with horizontal flip, vertical flip, small rotations (up to 15 degrees), brightness/contrast jitter, and Gaussian noise. All operations use OpenCV for speed.

Metrics

CiproSeg reports four segmentation metrics, all computed from the confusion matrix after thresholding the probability map:

MetricFormula
Dice2TP / (2TP + FP + FN)
IoU (Jaccard)TP / (TP + FP + FN)
PrecisionTP / (TP + FP)
RecallTP / (TP + FN)

A small epsilon (1e-8) is added to both numerator and denominator to avoid division by zero on empty frames. Metrics are computed per frame and then averaged across all frames in the series.

Two implementations exist: a PyTorch tensor version (used during training for quick validation) and a NumPy version (used during full-image tiled evaluation). Both produce identical results.

Extending CiproSeg

Adding a new model

Create a new file under src/ciproseg/models/, define your architecture, and register it:

# src/ciproseg/models/my_arch.py

import torch.nn as nn
from .registry import register_model

class MyArch(nn.Module):
    def __init__(self, in_channels=1, out_channels=1, **kwargs):
        super().__init__()
        # ... build layers ...

    def forward(self, x):
        # ... return raw logits (no sigmoid) ...
        return x

@register_model("my_arch")
def build_my_arch(**kwargs):
    return MyArch(**kwargs)

Then import the module in models/__init__.py:

from . import my_arch as _my_arch

Set model.name: my_arch in your config and train as usual.

Important
The @register_model decorator only fires when the module is imported. If you skip the import in __init__.py, the model will not be found by the registry at inference time (even if it works during training, which imports through a different path).

Adding a new dataset

Create a dataset class under src/ciproseg/data/datasets/ following the same pattern as ciproseg_ecoli.py: a build_index() function that returns a dict of series to frame lists, and a make_loso_folds() function. Wire it into build_datamodule() by checking the dataset.name field in the config.

Adding custom hooks

Subclass Hook from ciproseg.core.hooks and override the lifecycle methods you need. Then pass your hook to the Engine or add it to the HookList.

Testing

pytest tests/

The test suite covers model forward passes, dataset indexing and fold splitting, loss computation and gradients, checkpoint saving and loading, and training orchestration (via monkeypatched stubs). Tests use temporary directories and synthetic data, so no GPU or real dataset is needed.

For static analysis:

ruff check src/
mypy src/

Design Decisions

Single GPU only

No DDP, no torchrun, no DeepSpeed. The codebase includes basic distributed scaffolding (device resolution, rank checks, dist helpers) for possible future use, but the training loop is strictly single-GPU. This keeps the code simple, the experiments reproducible, and the debugging straightforward.

No mid-fold resume

Checkpoints are saved per fold, but training always restarts from fold 1. LOSO folds are fast enough on a single GPU that this is rarely a practical issue. The alternative (tracking fold progress, partial optimizer states, scheduler positions) would add substantial complexity for marginal benefit.

Self-contained checkpoints

Every .pt file stores the full config alongside weights. This means you can evaluate or run inference on a checkpoint months later without needing the original config file or remembering which experiment produced it.

Timestamp-based run directories

Each training run gets a unique directory based on the model name and current timestamp. Nothing is ever overwritten. If you want to compare two runs, both exist side by side on disk with their full configs and logs.

Temporal validation split

Within each fold, training and validation frames are split by temporal order (first 80% / last 20%) rather than randomly. This avoids information leakage from temporally adjacent frames that share similar cell configurations.

Validation frequency

Validation metrics are computed every 10 epochs rather than every epoch. This reduces overhead for large datasets while still providing enough resolution for checkpoint selection. The final epoch always triggers a validation pass regardless of the schedule.
